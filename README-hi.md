# dsh-token-usage

> टोकन उपयोग का विश्लेषण और मॉडल क्षमता रैंकिंग — DeepSeek Harness के लिए एक प्लगइन।

[English](README.md) | [中文](README-zh.md) | [Español](README-es.md) | [Português](README-pt.md) | हिन्दी

## What it does

यह प्लगइन **उसी host के अपने session logs** को पढ़ता है, रिकॉर्ड को provider और मॉडल
के हिसाब से समूहित करता है, और खपत की प्रवृत्ति, कैश हिट दर तथा मॉडल-वार उपयोग
दिखाता है। फिर यह **आपने वास्तव में जो मॉडल इस्तेमाल किए** उन्हें सार्वजनिक क्षमता
लीडरबोर्ड के साथ मिलाता है।

| क्षमता | प्रवेश बिंदु |
| --- | --- |
| उपयोग पैनल | साइडबार में "Token usage" → मुख्य पैनल |
| उपयोग JSON | `GET {prefix}/usage` (`days=` और `refresh=1` समर्थित) |
| मॉडल रैंकिंग | उपयोग पैनल के निचले हिस्से में |
| रैंकिंग JSON | `GET {prefix}/model-rank` (`refresh=1` समर्थित) |

**यह प्लगइन आपके किसी खाते को छूता नहीं।** यह केवल host के अपने session logs पढ़ता
है: कोई OAuth प्रवाह नहीं, कोई क्रेडेंशियल कॉपी नहीं, कोई मॉडल प्रोवाइडर पंजीकरण
नहीं, और किसी क्लाइंट में कोई बदलाव नहीं।

## How it relates to `dsh-agent-checkin`

**कोई संबंध नहीं।** दोनों प्लगइन स्वतंत्र हैं और अलग-अलग इंस्टॉल किए जा सकते हैं।
उपयोग पैनल 0.8.0 तक `dsh-agent-checkin` के भीतर था; 0.9.0 से यह अलग प्लगइन है: दोनों
न कोड साझा करते हैं, न cache फ़ाइलें, और एक-दूसरे को कॉल नहीं करते।

| | `dsh-agent-checkin` | `dsh-token-usage` |
| --- | --- | --- |
| क्या करता है | दैनिक चेक-इन, क्रेडिट बैलेंस, स्थानीय क्लाइंट्स को मॉडल प्रोवाइडर बनाना | टोकन उपयोग विश्लेषण, मॉडल क्षमता रैंकिंग |
| डेटा स्रोत | स्थानीय क्लाइंट्स का साइन-इन स्थिति | host के अपने session logs |
| क्या दूसरे की फ़ाइलें पढ़ता है? | —— | **नहीं** |

## Requirements

- DeepSeek Harness (`dsh`) 0.1.7 या उससे नया, कंबination में वेब UI के साथ
- Node.js `^22.19.0 || >=24.0.0`
- पढ़ने योग्य स्थानीय session log (डिफ़ॉल्ट `$DSH_HOME/sessions`, या `~/.dsh/sessions`)

## Installation

```bash
dsh plugin add dsh-token-usage
```

या प्रोफ़ाइल की `cordis.patch.yml` में एक पंक्ति जोड़ें:

```yaml
- id: dsh-token-usage
  name: dsh-token-usage
```

## Usage

### The usage panel

पैनल ऊपर से नीचे दिखाता है: सारांश आँकड़े (कुल खपत / आज / पिछले 7 दिन / कॉल
संख्या, साथ में कैश हिट, मिस और हिट दर), चार चार्ट (खपत की प्रवृत्ति, provider-वार
वितरण, सबसे ज़्यादा इस्तेमाल किए गए मॉडल, और आपके इस्तेमाल किए मॉडलों की क्षमता),
हर स्रोत का विस्तृत टेबल, मॉडल रैंकिंग जिसमें कार्य-आधारित सिफ़ारिशें हैं (कोडिंग /
तर्क / एजेंटिक / लंबा संदर्भ / विज़न / सबसे किफ़ायती) और स्कैन की असली लागत वाला फुटर।

समय-सीमा 7 / 30 / 90 दिन या "सभी" हो सकती है। "Refresh" ज़बरदस्ती दोबारा स्कैन करता
है; बाकी सब कैश से आता है।

### How the numbers are computed

| मापदंड | परिभाषा |
| --- | --- |
| प्रति रिकॉर्ड टोकन | `inputTokens + outputTokens + cacheReadTokens + cacheWriteTokens`, अलग-अलग जोड़े गए |
| हिट दर का हिस्सा | `input + cacheRead + cacheWrite` (**output के बिना** — जो बना वह डाला नहीं गया) |
| शून्य हिस्सा | "—" दिखाता है, **0% नहीं** ("पढ़ नहीं सका" और "सच में शून्य" अलग बातें हैं) |
| दिन की सीमा | स्थानीय समय क्षेत्र, UTC नहीं |
| "कुल" | पूरा इतिहास; कैश के तीनों आँकड़े उसी आधार पर, इसलिए आँकड़े मेल खाते हैं |

> **`totalTokens` फ़ील्ड क्यों नहीं**: वह पुराना माप है और उसकी गारंटी नहीं कि वह चार
> खंडों के योग के बराबर होगा। पेज का हर कुल अलग-अलग खंडों से जोड़ा जाता है।
>
> **सिर्फ़ `assistant/message` क्यों**: `assistant/attempt` में उसी उपयोग का एक
> प्रतिलिपि होता है; दोनों गिनने पर कुल दोगुना हो जाएगा।

### The incremental cache

Session logs केवल बढ़ते हैं, इसलिए हर बार सब कुछ दोबारा पढ़ने की कोई वजह नहीं। स्कैनर
हर फ़ाइल का `size + mtime` याद रखता है और सिर्फ़ बदली हुई फ़ाइलें दोबारा पढ़ता है।

- ठंडा पूरा स्कैन: कुछ दर्जन logs / दसियों MB, लगभग 1.4 सेकंड
- रोज़मर्रा की ताज़गी: कैश गर्म होने पर एक-अंक के मिलीसेकंड
- SQLite नहीं: कोई native निर्भरता नहीं, कोई schema प्रवास नहीं, कोई आधा-लिखा हुआ
  हालत नहीं

### The model leaderboard

दो स्रोत, सख़्ती से अलग: **क्षमता अंक** सार्वजनिक लीडरबोर्ड से आते हैं (OpenRouter का
`/api/v1/models`, बिना प्रमाणीकरण, जिसमें Artificial Analysis के intelligence /
coding / agentic सूचकांक हैं), और **दायरा** वे मॉडल हैं जो आपके session logs में सचमुच
दिखते हैं।

> ⚠️ **दायरे का कथन (पैनल पर छपा हुआ, छिपाया नहीं)**: लीडरबोर्ड सिर्फ़ यह बताता है कि
> "इस मॉडल का अंक क्या है", **यह नहीं** कि "आपको इसे बुलाने का अधिकार है या नहीं"।

### Leaderboard cache

लीडरबोर्ड दैनिक पैमाने पर बदलता है, इसलिए 6 घंटे (सेट करने योग्य) कैश में रहता है।
"Refresh board" बटन हमेशा कैश अनदेखा करता है। डाउनलोड की विफलता घातक नहीं है: पिछला
सही लीडरबोर्ड चलता रहता है और पैनल बताता है।

## Configuration

| फ़ील्ड | डिफ़ॉल्ट | अर्थ |
| --- | --- | --- |
| `statusRoute` | `/dsh-token-usage` | पैनल का HTTP उपसर्ग |
| `sessionsDir` | `''` | logs की जड़; ख़ाली यानी `$DSH_HOME/sessions` |
| `usageCacheSeconds` | `30` | स्कैन परिणामों की कैच अवधि |
| `rankCacheHours` | `6` | लीडरबोर्ड कैश अवधि, घंटों में |
| `rankScope` | `'used'` | `used` = केवल इस्तेमाल किए मॉडल; `all` = पूरा लीडरबोर्ड |

## Honest reporting

- **केवल loopback**: हर एंडपॉइंट केवल स्थानीय loopback अनुरोध स्वीकार करता है।
- **अंदाज़ा नहीं**: लीडरबोर्ड में न होने वाला मॉडल "—" दिखाता है, 0 नहीं; शून्य हिस्सा
  "—" दिखाता है, 0% नहीं। "पढ़ नहीं सका" कभी "शून्य पढ़ा" जैसा नहीं दिखता।
- **अधूरा स्कैन बताता है**: उसे "इस बार स्कैन पूरा नहीं हुआ" चिह्नित किया जाता है।
- **रैंकिंग में केवल वही मॉडल** जो आपने वास्तव में इस्तेमाल किए।

## Design trade-offs

| निर्णय | कारण | कीमत |
| --- | --- | --- |
| बहु-फ़्रेम zstd को हाथ से काटना | एक `.zstd` में हज़ारों स्वतंत्र फ़्रेम होते हैं; `zstdDecompressSync` केवल पहला खोलता है और **बाकी 99% चुपचाप खो देता है** | हम फ़्रेम सीमाएँ ख़ुद ढूँढते हैं |
| केवल `assistant/message` गिनना | `attempt` उसी माप की नकल करता है | `attempt` केवल डुप्लिकेट हटाने के लिए |
| `totalTokens` कभी न पढ़ना | पुराना फ़ील्ड चार खंडों के योग से नहीं मेल खाता | हम खंडों से जोड़ते हैं |
| मेमोरी कैश, SQLite नहीं | logs केवल बढ़ते हैं; मेमोरी ही रोज़मर्रा की ताज़गी मिलीसेकंड में कर देती है | host रीस्टार्ट के बाद एक ठंडा स्कैन |
| सार्वजनिक API से अंक | क्षमता **दूसरों की नापी** होनी चाहिए, हमारा अनुमान नहीं | नेटवर्क चाहिए; ऑफ़लाइन पुराना स्नैपशॉट चलता है |
| दायरा = देखे गए कॉल | क्षमता कार्ड से एक ही आधार, और किसी दूसरे प्लगइन पर निर्भर नहीं | इंस्टॉल किए पर कभी न इस्तेमाल किए मॉडल नहीं दिखते |
